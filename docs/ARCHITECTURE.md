# 架构与持续开发说明

## 设计目标

项目围绕以下约束设计：

1. 手机、平板和桌面端使用同一套页面；
2. 用户歌词只保存在本地，不需要后端；
3. 支持导出完全离线的单文件 HTML；
4. 打印必须使用浏览器真实尺寸测量，而不是只按字符数估算；
5. GitHub Pages 能够零服务器部署；
6. 仓库不携带完整歌词，避免把私人数据或受版权保护文本提交到公开仓库。

## 分层

### 页面层：`index.html`

负责语义结构、可访问性标签、Bootstrap 组件挂载点和打印选项。页面不内置曲目或用户歌词。

### 数据入口：`src/main.js`

加载 `src/data/songs.json`，完成基础错误处理，再异步加载主应用。

### 目录布局模块：`src/print/toc-layout.js`

负责目录标题权重、歌名换行权重、栏数选择和目录分页。它是无 DOM 的纯函数模块，可通过 Node 原生测试独立回归。

### 应用控制器：`src/app.js`

目前集中管理：

- 本地状态与版本迁移；
- 曲目检索、筛选、收藏和熟悉标记；
- 多版本、双语歌词编辑；
- JSON、Markdown 和离线 HTML 导入导出；
- 歌单解析与排序；
- 自适应打印测量、歌词分页和小册拼版；
- 调用独立目录布局模块生成演出目录；
- Service Worker 注册。

应用采用闭包隔离状态，公开环境中不产生全局 API；只有启动所需的数据和构建标记放到 `window`。

### 样式层：`src/styles/app.css`

包含：

- 响应式阅读界面；
- 明暗主题；
- 编辑器和歌单管理界面；
- A4、A5、小册打印尺寸；
- 动态字号、单双栏和双语布局；
- 打印页脚、页码和版权标记。

### 公开元数据：`src/data/songs.json`

只保存曲名、别名、来源、标签、说明和检索链接，不保存用户导入歌词。

### 构建层：`scripts/`

- `build.mjs`：复制静态资源、生成单文件 HTML、404 页面、版本信息和 Service Worker。
- `serve.mjs`：本地静态服务器，支持开发目录和 `dist/` 预览。
- `verify-project.mjs`：检查曲目 ID、页面挂载点、关键打印功能与私有备份误提交。

## 为什么使用 Bootstrap + 原生 ES Modules

歌词本主要是离线表单、目录、模态框、状态管理和打印排版，并不需要服务端渲染或复杂的组件生态。Bootstrap 提供稳定的响应式基础，原生模块减少运行时和依赖更新负担，Node 脚本则保证构建和 CI 可重复。

后续功能变多时，可按下列边界继续拆分，而不改变数据格式：

```text
src/
├── core/
│   ├── state.js
│   ├── storage.js
│   └── utils.js
├── features/
│   ├── editor/
│   ├── import-export/
│   ├── print/
│   └── setlists/
└── ui/
```

推荐在真正修改前先补测试，再逐步移动函数，避免一次性重写打印引擎。

## 打印引擎工作流程

严格页数模式对每首歌执行：

1. 构造原始行、短行合并、单栏、双栏、双语左右和上下等候选布局；
2. 把候选布局放入不可见的真实打印页测量容器；
3. 使用二分搜索寻找当前候选的最大可用字号；
4. 比较字号、栏数、压缩程度和阅读顺序，选择最优方案；
5. 单版本目标 1 页，多版本先尝试 1 页，再尝试最多 2 页；
6. 对最终页面再次检查 `scrollHeight` 与可用高度，防止裁切。

原始歌词不会因打印优化被改写。

## 状态版本

浏览器状态使用稳定的存储键，并在导入时归一化旧格式。数据升级原则：

- 不删除未知字段；
- 缺少多版本结构时自动建立默认版本；
- 已有 `lyricLibrary` 时优先保留多版本、翻译、默认版本和选择状态；
- 歌单和歌词分开归一化；
- 导出格式带 `format` 和 `exportedAt`。

## 发布架构

```text
Git push
   ↓
GitHub Actions
   ├── npm ci
   ├── npm run check
   ├── npm run build
   └── upload dist/
   ↓
GitHub Pages
   ↓
Cloudflare DNS / 可选代理
   ↓
自定义域名
```

`dist/` 不需要提交。自动部署始终从源代码重新构建，减少生成文件与源代码不一致的问题。
