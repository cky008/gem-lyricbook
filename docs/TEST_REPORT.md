# v5.1.3 目录实测分页与 PDF 回归测试报告

测试日期：2026-09-02

## 变更范围

v5.1.3 修复完整可选歌单能够安全放进一页时，仍被权重容量提前拆成 `62 + 10` 的问题。

目录权重模型继续用于快速筛选候选版式；最终是否单页、分页边界和页脚安全性改由浏览器在真实 A4／A5 DOM 中测量。只有所有完整页候选都不安全时，才二分寻找每页可容纳的最大章节／歌曲前缀。

本次没有改变备份格式、曲目 ID、歌词存储、歌曲正文分页或小册拼版顺序。

## 72 首完整可选歌单浏览器回归

打印范围使用“仅当前演出歌单”，包含全部可选章节并生成目录。三种版式都先渲染完整目录候选，再由真实 DOM 高宽、节点边界和页脚安全距离决定结果。

| 版式 | PDF 页／印刷面 | 目录页 | 最终目录版式 | 目录歌曲 | 内部链接 | 断链 | `overflowPages` |
|---|---:|---:|---|---:|---:|---:|---|
| A4 | 74 页 | 1 | 2 栏 / `standard` | 72 | 72 | 0 | `[]` |
| A5 | 74 页 | 1 | 2 栏 / `compact` | 72 | 72 | 0 | `[]` |
| A4 对折 | 38 个横向 A4 印刷面 | 1 个 A5 逻辑页 | 2 栏 / `compact` | 72 | 72 | 0 | `[]` |

A4 与 A5 的 74 页由 1 个目录页、72 个歌曲页和 1 个版权说明页组成。对折版先得到同样的 74 个 A5 逻辑内容页，再补齐到 76 个逻辑页并拼成 38 个横向 A4 印刷面。

三种版式都没有目录“（续）”，也没有回退为 `62 + 10`。目录条目顺序与公开歌单一致，每个歌曲 ID 恰好出现一次，页码在目录页数确定后重新计算。

程序化检查确认：

- 所有链接都指向对应歌曲的第一页；
- PDF 页面尺寸和方向与打印选项一致；
- A4 对折先使用 A5 逻辑页，再按骑马钉页序生成横向印刷面；
- 三种输出的 `overflowPages` 都为空；
- 没有缺失、重复、错序或隐藏裁切的目录条目。

## PNG 目视检查

三种 PDF 均使用 `pdftoppm` 渲染关键页，检查范围包括：

- 目录标题、第一项和最后一项；
- 章节交界、可选标签与长歌名；
- 页面底部、页码和至少 2 mm 的页脚安全距离；
- A4 对折第一张纸的正反面逻辑页顺序；
- 最后一页版权说明。

未发现目录裁切、稀疏续页、文字进入页脚、错误页码、黑块或乱码。

## 结论

v5.1.3 满足目录打印发布条件：完整 72 首可选歌单在 A4、A5 和 A4 对折逻辑页中均通过真实 DOM 单页测量；A4 使用双栏 `standard`，A5 与对折使用双栏 `compact`；三种 PDF 均为 72 个链接、0 个断链和 `overflowPages=[]`。

真实 iPhone／iPad Safari 与实体双面打印仍建议在发布后各做一次快速冒烟检查，因为浏览器 PDF 回归不能完全替代具体设备和打印机驱动。
