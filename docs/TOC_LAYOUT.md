# 自适应打印目录设计

## 问题背景

v5.1.1 使用固定容量和固定栏数：A4 默认三栏，A5／对折使用较小的单栏容量。这会导致两类浪费：

- 约 34 首的演出主流程被压在 A4 页面上半部，下面大面积留白；
- 同样的目录在 A5 或对折逻辑页中被机械拆成两页，第二页仍有大量空白。

v5.1.2 引入权重模型，能够根据标题、章节和歌名长度选择更合适的栏数。但权重仍是估算：完整 72 首可选歌单在真实 A5 页面能够安全放下时，估算容量会提前把它切成 `62 + 10`，产生稀疏续页。

## v5.1.3 目标

目录继续使用权重模型快速筛选候选，但最终是否单页、何时续页以及每页容纳多少内容，必须由浏览器在真实打印 DOM 中测量决定。

稳定基准包括：

- 34 首、5 个 Part 的合成主流程：A4、A5 和 A4 对折逻辑页都保持单页；
- 35 首、8 个章节的公开固定流程：选择最宽松的安全单页候选；
- 包含全部可选章节的 72 首公开歌单：A4 使用双栏 `standard`，A5 和 A4 对折逻辑页使用双栏 `compact`，三种版式均保持单个目录页；
- 真正超大的目录：只有完整候选全部失败后才续页，每页使用可安全容纳的最大前缀。

任何目录都不得依赖 `overflow: hidden` 掩盖裁切，也不得丢失、重复或改变歌曲顺序。

## 两阶段算法

### 1. 权重候选

`src/print/toc-layout.js` 继续估算标题换行、章节标题和歌曲条目占用。该估算用于即时页数预览和安排候选顺序，不直接作为最终分页结论。

A4 候选：

```text
单栏 roomy     估算容量 50
双栏 standard  估算容量 94
三栏 compact   估算容量 132
```

A5／对折逻辑页候选：

```text
单栏 roomy     估算容量 48
双栏 compact   估算容量 82
```

### 2. 真实 DOM 裁决

生成最终打印计划时，浏览器依次把完整目录候选渲染进真实 A4 或 A5 测量页。每个候选同时检查：

- page、content 和目录 flow 的 `scrollWidth/clientWidth` 与 `scrollHeight/clientHeight`；
- 页眉、目录标题、说明、章节标题、可选标签和每条歌曲的实际矩形；
- 所有正文是否位于内容区内；
- 正文底部与页码／页脚是否至少保留 2 mm；
- 渲染条目数量和顺序是否与输入歌曲 ID 完全一致。

第一个通过全部检查的完整候选立即成为单个目录页。72 首完整可选歌单因此不再被估算容量提前切开。

## 必要分页

只有所有完整页候选都实测失败时，才使用最紧凑版式分页：

1. 按原始章节和歌曲顺序建立当前页候选；
2. 二分搜索当前页能够安全容纳的最大歌曲前缀；
3. 在章节中间分页时为章节名添加“（续）”；
4. 对剩余内容重复相同测量，直到每首歌恰好出现一次；
5. 若单条内容仍无法安全容纳，明确报错并阻止输出，不隐藏文字。

分页后会根据最终目录页数重新计算歌曲页码，并反复测量直到页码与目录页数稳定。每个目录链接始终指向歌曲第一页。

## A4 对折

A4 对折先按 A5 尺寸生成和验证逻辑目录页，再与歌曲页、版权页和必要空白页一起参与骑马钉拼版。目录在拼版前只有一个 A5 逻辑页；物理 PDF 的一页包含两个逻辑页，不能把左右半页误判为两个目录页。

## 回归要求

```bash
npm test
```

`tests/toc-layout.test.mjs` 必须覆盖：

- 34 首／5 Part 的 A4、A5 与对折单页基准；
- 完整 72 首可选歌单先实测所有完整候选，不得回退为 `62 + 10`；
- 所有完整候选失败后选择最大安全前缀；
- 单条内容仍无法容纳时明确失败；
- 长目录标题换行计入安全检查。

涉及目录样式、测量或分页时，还必须生成 A4、A5 和 A4 对折 PDF，确认 `overflowPages=[]`，程序化检查页面尺寸、72 个内部链接和 0 个断链，并把关键页渲染为 PNG 目视检查。

完整发布阻断矩阵见 [打印目录排版回归测试计划](TOC_LAYOUT_TEST_PLAN.md)。
