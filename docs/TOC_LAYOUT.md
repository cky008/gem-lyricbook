# 自适应打印目录设计

## 问题背景

v5.1.1 使用固定容量和固定栏数：A4 默认三栏，A5／对折使用较小的单栏容量。这会导致两类浪费：

- 约 34 首的演出主流程被压在 A4 页面上半部，下面大面积留白；
- 同样的目录在 A5 或对折逻辑页中被机械拆成两页，第二页仍有大量空白。

## v5.1.2 目标

目录先选择“最少栏数、最大可读字号”的单页方案，只有单页确实放不下时才升级栏数或续页。

以深圳主流程 34 首、5 个 Part 为基准：

- A4：单栏、roomy 密度、1 页；
- A5：单栏、roomy 密度、1 个逻辑页；
- A4 对折：与 A5 共用逻辑页，目录只占 1 个半页；
- 不出现“（续）”。

## 算法

`src/print/toc-layout.js` 使用三层估算：

1. 根据中英文字符宽度估算歌名行数；
2. 章节标题和每首歌分别计算权重；
3. 按版式依次尝试布局档位。

A4 档位：

```text
单栏 roomy     容量 50
双栏 standard  容量 94
三栏 compact   容量 132
```

A5／对折档位：

```text
单栏 roomy     容量 48
双栏 compact   容量 82
```

若最紧凑档位仍放不下，才按章节和歌曲边界分页。分页时尽量保持章节完整，并对真正的续页添加“（续）”。

## 样式策略

- 单栏目录拥有更宽的正文区域、较大的标题、章节名和歌曲字号；
- A4 单栏最大宽度控制在适合长行阅读的范围，并居中放置；
- 双栏和三栏继续使用分隔线；
- A5／对折单栏使用专门的字号与间距，确保 34 首在一页内仍可读；
- PDF 内部链接结构不变。

## 回归要求

```bash
npm test
```

`tests/toc-layout.test.mjs` 必须验证：

- 34 首 A4 单栏单页；
- 34 首 A5／对折单栏单页；
- 超长目录会升级栏数或产生续页。

涉及样式或容量调整时，还必须运行浏览器 PDF 回归并渲染首个目录页目视检查。

## 标题安全

目录容量模型会额外计算标题换行高度。全部曲库中的演出目录使用歌单本身的简洁标题，并通过右上角 Kicker 区分上下文，避免长前缀把最后一首歌曲挤出页面。
